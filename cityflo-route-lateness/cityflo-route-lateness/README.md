# Route lateness: "is route X running late right now, and by how much?"

A runnable prototype for Cityflo's data take-home: ingest GPS pings and trips, reconstruct each route's timeline, compare
actual with expected progress, label a route late / on_time / early / unknown, estimate the delay, and explain the decision in
plain language for an operations dashboard.

> **Status: built on synthetic data.** The real Cityflo bundle was not available when this was built. All data in
> `cityflo_dummy_data/` was generated by `generate_dummy_data.py`, including planted failure cases. Results show the method works
> on known patterns. They are **not** findings about Cityflo's operations. See "Before submitting" below.

Start with **[SUBMISSION_NARRATIVE.md](SUBMISSION_NARRATIVE.md)**, which covers business understanding, the lateness definition,
data model, computation, validation, findings, false-late cases, limitations and future work.

## Layout

| Path | What it is |
|---|---|
| `SUBMISSION_NARRATIVE.md` | The nine-section narrative for the panel |
| `docs/design_notes.md` | Problem analysis, data model schemas, pipeline stages |
| `route_status_mvp.py` | The engine: `RouteStatusEngine.get_route_status(route_id, timestamp)` |
| `dashboard_explain.py` | Plain-language dashboard card (under 90 words) attached to every decision |
| `generate_dummy_data.py` | Seeded generator for the synthetic bundle (reproduces it byte for byte) |
| `cityflo_dummy_data/` | `routes`, `stops`, `trips`, `gps_pings`, `bookings`, `vehicle_trip_assignment`, answer key, scenario guide |
| `validation_scenarios.py` | 14 scenario tests (late, on time, early, gaps, duplicates, out-of-order, stoppage, hold, diversion) |
| `false_late_probes.py` | 9 probes where the bus is not truly late |
| `dashboard_checks.py` | 50-card check suite for length, jargon, structure and consistency |
| `dataset_analysis.py` | Blind operational analysis of the source tables (never reads the answer key) |
| `results/` | Captured output of every script plus the 07:45 verdicts and cards |

## Quickstart

```bash
pip install -r requirements.txt           # pandas, numpy
python route_status_mvp.py --data ./cityflo_dummy_data --ts "2026-06-17 07:45:00" --details
python validation_scenarios.py            # 14/14 pass
python false_late_probes.py               # 8 of 9 still labelled late (known weak spot)
python dashboard_checks.py                # all cards pass
python dataset_analysis.py                # operational findings
```

```python
from route_status_mvp import RouteStatusEngine
engine = RouteStatusEngine("./cityflo_dummy_data")
r = engine.get_route_status("R04", "2026-06-17 07:45:00")
r["status"], r["delay_minutes"], r["confidence"], r["dashboard"]["text"]
```

## Results at 07:45 on the synthetic bundle

| Route | Status | Delay (min) | Confidence | Simulated truth |
|---|---|---|---|---|
| R01 Borivali (W) to BKC | late | 12.0 | 0.85 | 12.0 |
| R02 Thane to Navi Mumbai | on_time | 1.0 | 0.71 | 1.0 |
| R03 Ghatkopar to BKC | unknown | n/a | 0.2 | no data (silent device) |
| R04 Thane to Andheri | late | 34.6 | 0.95 | 34.7 |

`status` can also be `unknown`, a deliberate deviation from the three requested values: missing data must not be read as on time.

## Known weaknesses

Eight of nine false-late probes are still labelled late (planted 8 min halt, transient queue, GPS drift, stale schedule and
others). Thresholds are uncalibrated; the timetable is assumed linear in distance. Details in the narrative, Sections 7 and 8.
